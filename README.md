# WhatsApp 双语翻译助手（v0.2.0）

<p>
  <img src="icons/icon128.png" width="64" height="64" alt="WhatsApp 翻译助手图标" align="left" style="margin-right: 12px;" />
</p>

在 WhatsApp Web 上显示收到消息的翻译；发消息时给出译文建议，由你自己手动复制粘贴、手动点击发送——**插件不会代替你自动操作发送消息**。

<br clear="left" />

> ⚠️ **重要提醒**：这是非官方第三方工具，不是 WhatsApp 官方功能。使用任何第三方工具都存在被 WhatsApp 风控系统限制或封号的风险。v0.2.0 已经去掉了"自动改写输入框+自动点击发送"这个高风险行为，只保留"读取显示"和"手动复制"两类低风险操作，但风险不可能降到零，请知情后自行判断是否使用，也请务必提前告知你分享插件的对象这一点。

## 安装步骤

1. 申请翻译引擎的 API Key（两选一，看你想用哪个）：
   - **DeepL**：参考 `deepl-api-key-guide.md`，注册免费 API Key（每月 50 万字符免费额度，不需要绑卡）。
   - **Google Translate**：参考 `google-api-key-guide.md`，需要在 Google Cloud Console 创建项目、绑卡、启用 Cloud Translation API。
2. 打开 Chrome，进入 `chrome://extensions`，打开右上角的"开发者模式"。
3. 点击"加载已解压的扩展程序"，选择本项目文件夹。
4. 打开 `web.whatsapp.com`，正常扫码登录。**首次使用会弹出风险告知弹窗**，需要点"我已知情，同意继续使用"才会启动插件的任何功能。
5. 点击浏览器工具栏里的插件图标：确认"启用翻译功能"开关是打开的，选翻译引擎、填入对应 API Key、选好"我的语言"，保存。

> 如果你是从旧版本升级上来的：设置项做了调整（Key 拆分成了每个引擎各自存储），旧版本存的 Key 不会自动迁移，需要重新打开设置面板填一次。

## 使用逻辑

- **收消息（只读显示，风险低）**：第一次收到某个联系人的消息时，插件会自动检测对方语言并记录下来，同时把译文显示在消息下方（灰色斜体）。这个过程只读取和展示，不涉及任何发送动作。
- **发消息（手动确认，不自动发送）**：在输入框打字时，如果已经知道对方语言（收到过对方至少一条消息）且和你的语言不同，输入框上方会出现一条译文建议 + "复制译文"按钮。点击复制后，**由你自己手动粘贴到想要的位置、手动点击发送**——插件全程不会修改输入框内容，也不会代替你点击发送按钮。
- 图片、语音、文件等非文字消息不做处理。
- **总开关**：设置面板顶部有"启用翻译功能"开关，关闭后插件停止一切监听和翻译动作（包括收消息翻译），开关状态实时生效，不用刷新页面。不需要翻译的时候可以随手关掉，减少后台资源占用。
- **首次使用风险告知**：第一次使用会弹出弹窗，说明这是非官方工具、可能有账号风险，用户点击同意后才会启动功能；不同意的话插件不会做任何事。这个确认状态存本地，正常使用只会弹一次。
- **额度保护**：插件会在本地统计当月已经发给翻译引擎的字符总数，一旦超过你设置的"每月字符上限"（默认 45 万，给常见的 50 万免费额度留余量），会自动停止调用翻译API，并在 WhatsApp 页面顶部弹出提示条。每个自然月自动清零，也可以在设置面板手动重置。
- **引擎兼容提示**：DeepL 只支持约 30 多种语言，插件内置了一份语言表，标记了哪些语言 DeepL 不支持（比如印地语、孟加拉语、乌尔都语、马来语、菲律宾语、斯瓦希里语、波斯语）。如果你在设置里选了这些语言、但当前引擎是 DeepL，会弹出提示并提供"一键切换到 Google Translate"的按钮。

## 权限说明（已做最小化）

- `manifest.json` 里只申请了 `storage` 一个通用权限，`host_permissions` 只限定了 `web.whatsapp.com` 和两个翻译引擎的域名，没有申请全站权限（`<all_urls>`），也没有申请 cookie/session 相关的权限。
- 插件不读取、不存储、不上传你的聊天记录或账号信息；翻译文本只会直接发给你自己配置的 DeepL / Google Key，不经过开发者的服务器中转。

## 已知限制 / 后续可以做的事

- **群聊**：当前逻辑是按"当前打开的聊天"记录一种语言，群聊里如果多人使用不同语言，翻译会不准确，需要后续按发言人单独处理。
- **选择器容易失效**：WhatsApp Web 经常小范围调整前端代码和 class 名。如果插件突然不生效了，多半是 `content.js` 顶部 `SELECTORS` 里的选择器过期，用浏览器开发者工具重新核对元素结构、更新即可。
- **引擎目前只接了两个**：DeepSeek、豆包等引擎还没接入，后续要加的话在 `background.js` 里参考 `callDeepL` / `callGoogleTranslate` 的写法加一个新函数、在 `translate()` 里加一个分支、在 `popup.html` 里加对应的设置项即可。
- **未做的部分**：翻译结果的持久化缓存（目前只有内存缓存，刷新页面会清空）、图标文件（`manifest.json` 里还没配置 icons，Chrome 会用默认图标，不影响功能）、订阅付费/账号体系（目前是纯本地单机版，商业化需要额外搭后端，见之前讨论）。
- **账号风险仍然存在**：去掉自动发送只是降低风险，不是消除风险。任何第三方工具介入 WhatsApp Web 页面，理论上都有被官方风控系统判定为异常客户端的可能。分享给别人用之前，一定要让对方先看到那个风险告知弹窗、自己点同意。

## 文件结构

```
whatsapp-translator/
├── manifest.json               # 插件配置（Manifest V3，权限已最小化）
├── background.js                # 调用翻译引擎API、管理设置/用量统计/缓存
├── content.js                    # 注入到 WhatsApp Web：翻译显示 + 译文建议 + 风险告知
├── styles.css                    # 译文展示、译文建议条、风险弹窗的样式
├── popup.html/js                # 设置面板（总开关、引擎、Key、语言、额度）
├── icons/                        # 插件图标（16/48/128px）
├── deepl-api-key-guide.md       # DeepL API Key 申请图文指南
├── google-api-key-guide.md      # Google Translate API Key 申请图文指南
├── xiaohongshu-recruitment-post.md  # 小红书招募测试用户文案
└── feedback-survey.md           # 分阶段用户反馈问卷
```
